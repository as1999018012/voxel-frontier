LWJGL ボクセルゲーム開発 · 準備編

Java開発環境セットアップ

LWJGL + Gradle で Minecraft 風の3Dゲームを作るための手動インストール手順。Windows 11のメインPCと、DGX Spark / PGX（Linux, aarch64）の両方をカバーする。上から順に進めれば、コマンド一つで検証しながら環境が整う。

1

JDKをインストールする

配布元は Eclipse Temurin（旧 AdoptOpenJDK）。LTS版の JDK 21 を選ぶ。

  1. adoptium.net にアクセスする。
  2. OS: Windows、Architecture: x64、Version: 21 - LTS、Package Type: JDK を選び、.msi インストーラーをダウンロードする。
  3. ダウンロードした .msi を実行する。
  4. 「Custom Setup」画面が出たら、次の2項目を必ず有効にする（初期状態で無効になっていることがある）。
オプション設定
Set JAVA_HOME variableWill be installed on local hard drive（有効化する）
Add to PATHWill be installed on local hard drive（有効化する）
Tip

この2つを有効にしておけば、後で環境変数を手動編集する必要がなくなる。インストーラーの指示通り進めれば完了。

DGX Spark / PGX は Grace CPU 系の aarch64（ARM64） 機であり、通常のx86_64向けPCとはバイナリの種類が異なる。まずアーキテクチャを確認する。

uname -m
期待される出力
aarch64
重要: 以降、JDK・Gradle・（将来の）LWJGLネイティブライブラリは、Windows機ではx64、DGX Spark / PGXではaarch64 / arm64版を選ぶ。同じプロジェクトでも機種ごとに取得するバイナリの種類が変わる点に注意。
  1. adoptium.net にアクセスし、OS: Linux、Architecture: aarch64、Version: 21 - LTS、Package Type: JDK、Type: .tar.gz を選んでダウンロードする。
  2. ターミナルで /opt 配下に展開する。
sudo mkdir -p /opt/temurin21
sudo tar -xzf ~/Downloads/OpenJDK21U-jdk_aarch64_linux_hotspot_*.tar.gz \
  -C /opt/temurin21 --strip-components=1
  1. ~/.bashrc（zshなら ~/.zshrc）の末尾に JAVA_HOME と PATH を追記する。
echo 'export JAVA_HOME=/opt/temurin21' >> ~/.bashrc
echo 'export PATH=$JAVA_HOME/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
Tip

複数ユーザーで使う機種なら ~/.bashrc の代わりに /etc/profile.d/temurin21.sh に同じ2行を書いて sudo chmod +x しておくと全ユーザーに反映される。

2

JDKの動作確認

インストール後は必ず新しいPowerShellウィンドウを開き直すこと。既存のウィンドウはPATHの更新を反映しない。

同じターミナルで続けて構わない（source ~/.bashrc 済みのため）。新しいターミナルを開いた場合は自動的に反映される。

java -version
javac -version
期待される出力例
openjdk version "21.0.x" ...
javac 21.0.x
つまずいたら

'java' は認識されていません と出る場合、(1) PowerShellを新規に開き直したか、(2) PC自体を再起動する必要がある場合がある、を確認する。それでも直らなければ「システム環境変数の編集」→「環境変数」で Path に JDKの bin フォルダ（例: C:\Program Files\Eclipse Adoptium\jdk-21.x.x-hotspot\bin）が入っているか目視で確認する。

つまずいたら

command not found: java と出る場合、echo $JAVA_HOME と cat ~/.bashrc | grep JAVA_HOME で追記が反映されているか確認する。ログインシェルが bash 以外（zsh等）の場合は該当する設定ファイル（~/.zshrc）に書いたか見直す。

3

Gradleをインストールする

GradleはZIPを展開してPATHを通すだけ。インストーラーは無い。Gradle自体は純Java製なのでOSやCPUアーキテクチャを問わず同じZIPが使える。

  1. gradle.org/releases から最新の Binary-only ZIP（例: gradle-8.x-bin.zip）をダウンロードする。
  2. ZIPを C:\Gradle\gradle-8.x に展開する（パスにスペースや日本語を含めない。作業フォルダが「ゲーム製作所」配下だと問題が起きやすいため、Gradle本体は別の英数字パスに置く）。
  3. スタートメニューで「環境変数を編集」と検索し、「ユーザー環境変数」の Path を選択して「編集」→「新規」。
  4. C:\Gradle\gradle-8.x\bin を追加してOKで閉じる。
  1. gradle.org/releases から同じバージョンの Binary-only ZIP（例: gradle-8.x-bin.zip）をダウンロードする（Windows側と揃えておくとチーム内で挙動差が出ない）。
  2. /opt に展開し、PATHに追記する。
sudo unzip -d /opt/gradle ~/Downloads/gradle-8.*-bin.zip
echo 'export PATH=/opt/gradle/gradle-8.*/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
Tip

unzip が無い場合は sudo apt install unzip を先に実行する。ワイルドカード（gradle-8.*）はバージョン番号を毎回打たなくて済むようにしているだけなので、実際に展開されたフォルダ名に合わせて確認しておく。

なぜ必要か

プロジェクト自体には後で Gradle Wrapper（gradlew）を同梱するので、完成後は各機種にGradle本体が無くてもビルドできる。今インストールするのは、プロジェクトを最初に作る作業とIDE連携のため。

4

Gradleの動作確認

こちらも新しいPowerShellウィンドウで実行する。

同じターミナルでよい。

gradle -v
期待される出力
------------------------------------------------------------
Gradle 8.x
------------------------------------------------------------
...
JVM: 21.0.x (Eclipse Adoptium ...)
期待される出力
------------------------------------------------------------
Gradle 8.x
------------------------------------------------------------
...
JVM: 21.0.x (Eclipse Adoptium ...)
OS: Linux ... aarch64
つまずいたら

Gradleが「JVM」欄で別バージョンのJavaを拾うことがある。複数JDKが入っている場合は環境変数 JAVA_HOME がTemurin 21を指しているか echo $env:JAVA_HOME で確認する。

つまずいたら

出力末尾の「OS:」行が aarch64 になっているか確認する。もし x86_64 と出た場合、誤ってx86_64向けの見慣れたコマンドやDockerイメージ経由で実行している可能性があるので、直接ホストの uname -m と一致するか見直す。

5

エディタ（任意）

必須ではないが、Gradle連携とデバッガが揃っている方が3D描画のデバッグが格段に楽になる。

  • IntelliJ IDEA Community Edition（無料）— Gradleプロジェクトを開くだけで依存関係を自動解決してくれる。今回のLWJGL構成には最も相性が良い。Windows・Linux（aarch64含む）双方にネイティブビルドがある。
  • VS Code + "Extension Pack for Java" でも代替可能。こちらもLinux ARM64版が公式に配布されている。

次のステップ

ここまでの3つのコマンド（java -version / javac -version / gradle -v）が、Windows機とDGX Spark / PGXの両方で期待通りに表示されたら、環境構築は完了。

先取りメモ: 次に作るGradleプロジェクトでは、LWJGLのネイティブライブラリ（lwjgl-natives）をWindowsでは natives-windows、DGX Spark / PGXでは natives-linux-arm64 として振り分ける設定を build.gradle に入れる。1つのbuild.gradleで両機種に対応できるので、機種ごとに設定を書き直す必要はない。
  1. Gradleプロジェクトの雛形を作成（build.gradle に LWJGL 3 のネイティブ依存を設定）
  2. GLFWでウィンドウを開き、OpenGLコンテキストを初期化する「Hello Triangle」で描画パイプラインを確認
  3. ボクセル1個の描画 → チャンク（16×16×16）描画 → 複数チャンクのワールド生成、の順で拡張

確認コマンドの結果を教えてもらえれば、続けてプロジェクトの雛形を作成します。
